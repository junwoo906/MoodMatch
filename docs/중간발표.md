# MoodMatch 중간발표 자료 (슬라이드별 초안)

## 슬라이드 1. 과제 주제
**MoodMatch — AI 기반 개인 맞춤 팝업·카페·전시 추천 서비스**

- 문제: 팝업·전시가 너무 많고 빨리 바뀌어서, 내 취향에 맞으면서 지금 운영 중인 곳을 찾기 어렵다.
- 해결: 사용자의 취향을 분석하고 실제 장소 데이터와 비교해 맞춤 추천하며, 운영 상태(기간·종료 여부)까지 확인한다.
- 차별점: "GPT에게 추천해 달라고 묻는 서비스"가 아니다. 취향과 장소를 **같은 기준의 데이터로 구조화**하고, 순위는 **코드(추천 알고리즘)가 계산**한다.

## 슬라이드 2. 전체 과제의 입력 및 출력

| 구분 | 내용 |
|---|---|
| 입력 (사용자) | 취향 질문 답변(체험·분위기·굿즈·사진·가격), 방문 날짜, 희망 지역 |
| 입력 (데이터) | 팝업·카페·전시 정보: 이름, 지역, 운영 기간, 가격, 소개글, 출처 |
| 처리 | ① AI 취향 분석 → ② AI 장소 특징 추출 → ③ 조건 필터(날짜·지역·가격·운영 상태) → ④ 취향 매칭 점수 계산 → ⑤ AI 추천 이유 생성 |
| 출력 | 맞춤 추천 장소 목록(순위·점수), 장소별 추천 이유, 좋아요/별로예요 피드백 버튼 |

흐름: `취향 질문 → 취향 프로필 → (장소 DB와 비교) → 필터링 → 순위 계산 → 추천 + 이유 → 피드백 반영`

## 슬라이드 3. 사용 AI의 종류, 입력, 출력

사용 AI: **OpenAI GPT API** (개발 과정에서는 ChatGPT로 프롬프트 검증)

| AI 작업 | 입력 | 출력 |
|---|---|---|
| ① 취향 분석 | 사용자 답변 (예: "체험형, 귀여운 분위기, 사진 촬영, 무료 입장 선호") | 태그별 선호도 프로필 (JSON) |
| ② 장소 특징 추출 | 팝업·전시 소개글 | 정해진 태그로 구조화한 데이터 (체험 여부, 포토존, 굿즈, 분위기, 가격대) |
| ③ 추천 이유 설명 | 사용자 취향 + 코드가 이미 정한 추천 결과와 일치 태그 | 사용자가 이해하기 쉬운 추천 이유 문장 |

AI와 코드의 역할 구분:
- **AI**: 자연어를 구조화된 데이터로 변환하고, 결과를 설명하는 역할
- **코드**: 필터링과 점수 계산 → 같은 입력이면 항상 같은 결과가 나오고, 테스트할 수 있다.

공통 태그 기준: 활동(체험, 사진, 굿즈, 관람, 음식) / 분위기(귀여운, 조용한, 트렌디, 예술적, 레트로) / 가격(무료, 1만원 이하, 1~3만원, 3만원 초과)

## 슬라이드 4. AI 사용 실 사례 ① — 장소 특징 추출 (ChatGPT 실행 화면 캡처 넣기)

ChatGPT에 아래 프롬프트를 넣고, 실제 팝업 소개글 1개로 실행한 화면을 캡처한다.

```
너는 팝업·전시 소개글에서 특징을 추출하는 분석기야.
아래 소개글을 읽고 정해진 태그 안에서만 골라 JSON으로만 답해.

허용 태그
- activities: 체험, 사진, 굿즈, 관람, 음식
- moods: 귀여운, 조용한, 트렌디, 예술적, 레트로
- price: 무료, 1만원 이하, 1~3만원, 3만원 초과, 알수없음
- reservation: 필요, 불필요, 알수없음

규칙: 소개글에 근거가 없는 태그는 넣지 마. 각 태그마다 근거 문장을 evidence에 짧게 적어.

출력 형식
{"activities": [], "moods": [], "price": "", "reservation": "", "evidence": {}}

소개글:
(여기에 실제 팝업 공식 안내 문구를 붙여넣기)
```

슬라이드에 넣을 내용: 입력 소개글 → AI 출력 JSON → "이 결과가 장소 DB의 특징 데이터로 저장된다"

## 슬라이드 5. AI 사용 실 사례 ② — 추천 결과와 추천 이유

추천 알고리즘 시연 결과 (`demo/recommend.py`, 테스트 데이터 8개, 방문일 2026-10-31)

| 사용자 | 1위 | 2위 | 3위 |
|---|---|---|---|
| A: 체험·사진·귀여운·무료 | 캐릭터 팝업 A (1.00) | 레트로 게임 팝업 C (0.69) | 디저트 팝업 E (0.65) |
| B: 관람·조용한·예술적 | 미디어아트 전시 B (0.93) | 사진전 F (0.80) | 북카페 D (0.39) |

- 취향이 다른 사용자에게 **서로 다른 결과**가 나온다.
- 종료된 팝업 G는 **운영 종료**로, 향수 팝업 H는 **방문일에 아직 시작 전**이라서 자동으로 제외된다.

AI ③ 추천 이유 프롬프트 (ChatGPT 실행 화면 캡처):
```
사용자 취향: 체험(1순위), 사진(2순위), 귀여운 분위기, 무료 선호
추천 장소: 캐릭터 팝업 A (1위, 이미 확정된 순위이므로 바꾸지 마)
일치한 특징: 체험, 사진, 굿즈, 귀여운, 트렌디 / 무료 입장
이 장소를 추천하는 이유를 친근한 말투로 2문장 이내로 써줘.
```

점수 계산식: `0.4×활동 일치 + 0.3×분위기 일치 + 0.15×종류 선호 + 0.15×가격 적합도`

## 슬라이드 6. 기획 발전 과정
- 처음: "AI가 팝업을 추천해 주는" 아이디어
- 발전 1: 사용자 취향과 장소 정보를 **같은 기준의 태그 데이터**로 구조화
- 발전 2: AI(분석·설명)와 알고리즘(필터·순위)의 **역할 분리**
- 발전 3: 검색 API의 저장·재가공 제한을 고려해서, **공식 출처로 확인한 정보만** 저장하는 수집 구조로 설계
- 발전 4: 소규모 데이터로 먼저 검증하고, 이후 자동 수집으로 확장

## 슬라이드 7. 최종 발표까지 계획

| 기간 | 할 일 | 결과물 |
|---|---|---|
| 1주차 | 실제 팝업·전시·카페 15~20개 수집(공식 출처), Supabase DB 구축 | 장소 DB |
| 2주차 | GPT API 연동: AI ② 장소 특징 자동 추출, 사람이 붙인 태그와 정확도 비교 | 특징 추출 기능, 정확도 결과 |
| 3주차 | 취향 질문 화면 + 추천 결과 화면(웹), AI ③ 추천 이유 연동 | 처음부터 끝까지 동작하는 웹 |
| 4주차 | 좋아요/별로예요 피드백 반영, 가상 사용자로 추천 결과 검증 | 검증 결과 |
| 5주차 | 정기 업데이트(종료 장소 자동 제외, 신규 후보 등록), API 약관 확인 | 자동 갱신 기능 |
| 6주차 | 테스트, 버그 수정, 최종 발표 준비 | 최종 시연 |

기술 스택: Python(추천 알고리즘), OpenAI GPT API, Supabase(DB), 웹 화면, 스케줄러(하루 1회 갱신)
